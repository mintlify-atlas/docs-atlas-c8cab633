title: "Get started with ContaFácil"
sidebarTitle: "Quickstart"
description: "Clone, configure a Supabase connection, run three SQL migrations, and have a fully working accounting API and UI running locally in minutes."
---

ContaFácil ships as a single Node.js process — there is no Docker requirement, no build pipeline, and no separate front-end compilation step. Once you point it at a Supabase project and run the schema migrations, both the REST API and the browser UI are live at `http://localhost:3000`.

<Steps>

<Step title="Prerequisites">

Make sure the following are available on your machine before you begin:

- **Node.js ≥ 22** — ContaFácil uses the `engines` field in `package.json` to enforce this. Check your version:

```bash
node --version
# v22.x.x or higher
```

- **A Supabase project** — Create a free project at [supabase.com](https://supabase.com). You will need the **Session pooler** connection string from **Project Settings → Database → Connection string** (select the *Session* mode tab). It looks like:

```
postgresql://postgres.PROJECT_REF:DB_PASSWORD@aws-0-us-west-2.pooler.supabase.com:5432/postgres
```

<Info>
  Use the **Session pooler** (port `5432`), not the Transaction pooler (port `6543`). ContaFácil uses explicit `BEGIN / COMMIT` transactions that require a persistent session connection.
</Info>

</Step>

<Step title="Clone and install dependencies">

Clone the repository and install the four runtime dependencies (`express`, `pg`, `cors`, `dotenv`):

```bash
git clone https://github.com/GersonBarrientos/ContaFacil.git
cd ContaFacil
npm install
```

</Step>

<Step title="Configure environment variables">

Copy the provided example file to create your local `.env`:

```bash
cp .env.example .env
```

Open `.env` and replace the placeholder values with your real Supabase credentials:

```env
PORT=3000
SUPABASE_DB_URL=postgresql://postgres.PROJECT_REF:DB_PASSWORD@aws-0-us-west-2.pooler.supabase.com:5432/postgres
```

| Variable | Description |
|---|---|
| `PORT` | Port the Express server listens on (default `3000`) |
| `SUPABASE_DB_URL` | Full PostgreSQL connection string from the Supabase Session pooler |

<Warning>
  Never commit `.env` to version control. The repository already includes a `.gitignore` entry for it, but double-check before pushing to a shared remote.
</Warning>

</Step>

<Step title="Run the database migrations">

ContaFácil ships three ordered SQL migration files under `database/`. Run them **in sequence** inside the **Supabase SQL Editor** (Dashboard → SQL Editor → New query):

1. **`database/001_supabase_empresas_libros_dinamicos.sql`**  
   Creates the core schema: `empresas`, `usuarios`, `libros_diarios`, `asientos`, and supporting tables.

2. **`database/002_balance_comprobacion.sql`**  
   Adds views and functions required by the trial-balance and financial-statement endpoints.

3. **`database/003_kardex.sql`**  
   Creates `kardex_articulos` and `kardex_movimientos` for perpetual inventory tracking.

Paste the contents of each file into the SQL Editor and click **Run**. Wait for a success message before moving to the next file.

</Step>

<Step title="Start the server">

```bash
npm start
```

You should see output similar to:

```
Servidor API corriendo en http://localhost:3000
Vista Frontend disponible en http://localhost:3000/index.html
✅ Conexión exitosa a Supabase PostgreSQL en la nube ☁️
```

If the last line shows a connection error instead, double-check that `SUPABASE_DB_URL` in your `.env` matches the Session pooler URL exactly — including the project reference and password.

</Step>

<Step title="Verify: health check, register a company, and log in">

**1. Confirm the API is reachable and the database connection is healthy:**

```bash
curl http://localhost:3000/api/health
```

Expected response:

```json
{"ok":true,"database":"supabase-postgresql"}
```

---

**2. Register your first company and admin user:**

```bash
curl -X POST http://localhost:3000/api/registro \
  -H "Content-Type: application/json" \
  -d '{
    "nombre_legal": "Mi Empresa",
    "email": "admin@miempresa.com",
    "password": "secret"
  }'
```

Expected response:

```json
{
  "ok": true,
  "empresa_id": 1,
  "email": "admin@miempresa.com",
  "nombre": "Admin Mi Empresa"
}
```

Save the returned `empresa_id` — you will pass it as a query parameter to most module endpoints (e.g. `?id_empresa=1`).

---

**3. Log in with the credentials you just created:**

```bash
curl -X POST http://localhost:3000/api/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "admin@miempresa.com",
    "password": "secret"
  }'
```

Expected response:

```json
{
  "ok": true,
  "empresa_id": 1,
  "email": "admin@miempresa.com",
  "nombre": "Admin Mi Empresa"
}
```

A `401` response means the email/password combination was not found or the user's `estado` is not `ACTIVO`. Re-check the values you passed to `/api/registro`.

</Step>

</Steps>

<Tip>
  The browser-based UI is available at **http://localhost:3000** (or `http://localhost:3000/index.html`). It communicates with the same API you just verified and requires no additional setup — open it in any modern browser once the server is running.
</Tip>
